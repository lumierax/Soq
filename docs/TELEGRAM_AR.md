# بوت حقيقي على جهازك وتنبيهات تيليغرام

يمكن تشغيل خادم نبض على حاسوبك دون اشتراك استضافة. يبقى الحاسوب يعمل ومتصلًا بالإنترنت؛ إطفاؤه أو دخوله في السكون يوقف المسح والمتابعة. **تيليغرام يستقبل التنبيهات؛ تنفيذ البوت وحساب التحليل يجريان على حاسوبك.** وقف الخسارة والهدف المؤكدان يبقيان على Binance عند إغلاق البرنامج.

## إعداد التنبيهات

1. أنشئ بوتًا عبر حساب Telegram الرسمي `@BotFather`، ثم افتح محادثتك مع البوت واضغط **Start**. لا ترسل له مفاتيح Binance.
2. في ملف `backend/.env` الخاص بحاسوبك أضف التوكن ومعرّف المحادثة الرقمي `chat_id`:

```dotenv
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
```

اكتب القيم الفعلية بعد علامة `=` على جهازك فقط. معرّف المجموعة يبدأ عادة بعلامة سالب؛ المعرف يجب أن يكون رقميًا، وليس اسم المستخدم. لا ترفع ملف `.env` إلى GitHub ولا تضع التوكن في الهاتف أو رابط متصفح. أعد تشغيل الخادم بعد تعديل الملف.

تصلك إشعارات تفعيل البوت، الدخول بعد تأكيد الحماية، الإغلاق مع النتيجة المؤكدة، الإيقاف المؤقت، قاطع الخسارة، وأخطاء التداول. كل إشعار يوضح **محاكاة / اختبار / تداول حقيقي**. التنبيهات لا تحتوي مفاتيح Binance. لا توجد أوامر فتح صفقات أو تفعيل تداول عبر محادثة تيليغرام في هذا الإصدار.

فشل إرسال إشعار لا يؤخر وقف الخسارة ولا يغير حالة التداول. الإرسال محدود بمحاولة كل ثلاث ثوانٍ، ومحاولة إضافية واحدة للأخطاء المؤقتة؛ يُدمج الخطأ المكرر خلال خمس دقائق. الطابور يحتفظ بآخر 64 إشعارًا، وقد تضيع إشعارات عند الانقطاع أو الإغلاق. انقطاع الشبكة قد يجعل نتيجة التسليم غير مؤكدة ويؤدي إلى إشعار مكرر. سجل البوت المحلي هو مرجع التنفيذ.

## تشغيل الحاسوب

نزّل مصادر المشروع من GitHub وفكها في مجلد `nabd`. تحتاج Python 3.12، وNode.js 22 لبناء واجهة التحكم المحلية. الأوامر التالية من مجلد المشروع. إذا كان ملف `backend/.env` موجودًا بالفعل، احتفظ به ولا تنسخ فوقه.

### Linux

للتثبيت الأول:

```bash
cp backend/.env.example backend/.env
python3 -c "from pathlib import Path; import secrets; p=Path('backend/.env'); p.write_text(p.read_text().replace('replace-with-a-long-random-token', secrets.token_urlsafe(36)))"
cd frontend
npm ci
npm run build
cd ..
bash scripts/run-backend.sh
```

توليد رمز التطبيق في الأمر أعلاه يحفظه في الملف دون طباعته. يشغّل السكربت Python ويثبت المتطلبات في `.venv`. افتح `http://127.0.0.1:8000` **في متصفح الحاسوب** واترك البرنامج يعمل. في إعدادات الواجهة اختر **«خادم البوت»**، وأدخل عنوان الخادم `http://127.0.0.1:8000` ورمز `APP_TOKEN` من ملفك المحلي. الوضع المباشر الافتراضي يعرض السوق فقط ولا يدير البوت؛ الرمز يبقى في ذاكرة الجلسة.

لتشغيله تلقائيًا، يمكن إعداد خدمة systemd للمستخدم بعد التثبيت. يستخدم أمرها المسارات المطلقة على جهازك:

```ini
[Unit]
Description=NABD local futures service
After=network-online.target

[Service]
WorkingDirectory=/home/YOUR_USER/nabd/backend
ExecStart=/home/YOUR_USER/nabd/.venv/bin/uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
Restart=on-failure
RestartSec=5
TimeoutStopSec=120

[Install]
WantedBy=default.target
```

احفظه باسم `~/.config/systemd/user/nabd.service`، وعدّل `YOUR_USER` ومجلد المشروع، ثم شغّل `systemctl --user daemon-reload` و`systemctl --user enable --now nabd`. هذه الخدمة تعمل في جلسة المستخدم؛ استمرارها بعد تسجيل الخروج يتطلب إعداد المستخدم في نظامك. أوقف التشغيل اليدوي قبل تشغيل الخدمة لتجنب نسختين أو تعارض المنفذ.

### Windows — PowerShell

للتثبيت الأول:

```powershell
Copy-Item backend/.env.example backend/.env
py -3.12 -c "from pathlib import Path; import secrets; p=Path('backend/.env'); p.write_text(p.read_text().replace('replace-with-a-long-random-token', secrets.token_urlsafe(36)))"
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Set-Location frontend
npm ci
npm run build
Set-Location ../backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

افتح `http://127.0.0.1:8000` في متصفح الحاسوب، ثم في الإعدادات اختر **«خادم البوت»** وأدخل `http://127.0.0.1:8000` ورمز `APP_TOKEN` المحلي؛ الوضع المباشر الافتراضي لا يدير البوت. للتشغيل التلقائي، أضف مهمة **At log on** في Task Scheduler: البرنامج هو المسار الكامل إلى `.venv\Scripts\python.exe`، و**Start in** مجلد `backend`، والوسائط هي `-m uvicorn app.main:app --env-file .env --host 127.0.0.1 --port 8000 --workers 1 --no-access-log`. شغّل نسخة واحدة فقط وامنع سكون الحاسوب أثناء إدارة مراكز.

## ربط iPhone بحاسوبك مجانًا عبر Tailscale

هذا المسار يستخدم [خطة Tailscale Personal المجانية](https://tailscale.com/docs/reference/free-plans-discounts) للاتصال الخاص بين أجهزتك. لا يحتاج اشتراك استضافة أو فتح منفذ في الراوتر.

1. ثبّت Tailscale على الحاسوب وiPhone من [الموقع الرسمي](https://tailscale.com/download)، وسجّل الجهازين بالحساب الشخصي نفسه. شغّل اتصال Tailscale على الهاتف.
2. شغّل خادم نبض على الحاسوب بالأوامر السابقة. يبقى مستمعًا على `127.0.0.1:8000`. من لوحة Tailscale، فعّل **MagicDNS** وشهادات **HTTPS**؛ قد يعرض الأمر التالي رابط الموافقة على تفعيل HTTPS عند أول استخدام.
3. في طرفية الحاسوب افحص الإعداد الحالي قبل تغييره:

```bash
tailscale serve status
```

إذا كان HTTPS على المنفذ `443` يخدم برنامجًا آخر، لا تستبدله بهذه الأوامر؛ خصّص منفذًا آخر بالتنسيق مع مسؤول الجهاز. لا تستخدم `tailscale serve reset` لأنه يمسح إعدادات Serve الأخرى.

4. إذا لم تكن هناك خدمة Serve على هذا المنفذ، شغّل الربط الخاص ثم اعرض عنوانه:

```bash
tailscale serve --bg --https=443 http://127.0.0.1:8000
tailscale serve status
```

قد تحتاج إلى `sudo` قبل أوامر Tailscale على Linux. في Windows استخدم PowerShell بعد تثبيت التطبيق. النتيجة تعرض عنوان HTTPS فعليًا ينتهي بـ `.ts.net`، ويجب أن توضح أنه متاح داخل شبكتك الخاصة **tailnet**. هذا **Serve خاص**؛ لا تستخدم Funnel الذي ينشر الخدمة للإنترنت.

5. على iPhone المتصل بـ Tailscale، افتح العنوان الفعلي مع `/api/health` للتحقق من وصول الهاتف إلى الخادم. نجاحه يؤكد الاتصال بالخادم؛ صلاحية Binance وحالة السوق تظهران داخل نبض. في تطبيق IPA اختر **«خادم البوت»**، وانسخ عنوان HTTPS نفسه **دون** `/api/health`، ثم أدخل `APP_TOKEN` من ملفك المحلي. لا تضع التوكن في الرابط أو Telegram. العنوان `127.0.0.1` داخل الهاتف لا يصل إلى الحاسوب.
6. أبقِ الحاسوب مستيقظًا وخادم نبض وTailscale يعملان. خيار `--bg` يحفظ ربط Serve ويعيده بعد إعادة تشغيل Tailscale؛ لا يشغّل خادم Python تلقائيًا. يلزم اتصال Tailscale على iPhone كلما أردت التحكم. إغلاق الهاتف أو فصل اتصاله لا يوقف البوت على الحاسوب، ما دام الحاسوب متصلًا بالإنترنت.

لإيقاف **الربط الذي أنشأته أعلاه فقط** على `443`، مع إبقاء أعلام الأمر الأصلي:

```bash
tailscale serve --bg --https=443 off
tailscale serve status
```

لا تنفذ أمر الإيقاف إذا جرى لاحقًا تخصيص المنفذ لخدمة أخرى. إيقاف Serve يمنع وصول الهاتف؛ لإيقاف التداول استخدم أدوات البوت نفسها. التفاصيل الرسمية: [Serve](https://tailscale.com/docs/features/tailscale-serve) و[أوامر التشغيل والإيقاف](https://tailscale.com/docs/reference/tailscale-cli/serve).

استخدم **تطبيق IPA** لإدارة البوت بهذا المسار. يمكن لقيود المتصفح الخاصة بالشبكات الخاصة وDNS وCORS أن تمنع واجهة GitHub Pages من الوصول، حتى مع السماح بأصلها في الخادم. صفحات السوق المباشر تعمل دون Tailscale. هذا الربط لا يغيّر بلد اتصال الحاسوب بـ Binance، ولا يحتاج exit node، ولا يعالج رفض Binance الجغرافي.

## مفاتيح التداول

مفاتيح Binance منفصلة عن توكن Telegram وتُحفظ في `backend/.env` فقط. للاختبار استخدم مفاتيح Futures Testnet واختر وضع Testnet. للمال الحقيقي تحتاج مفاتيح Binance المناسبة بصلاحية Futures دون سحب، و`ALLOW_LIVE_TRADING=true`، وتأكيد `ENABLE LIVE TRADING` في واجهة التحكم. هذه الملفات لا تفعّل التداول الحقيقي تلقائيًا. بعد إعادة تشغيل الخدمة تبقى إضافة صفقات جديدة معطلة حتى التفعيل الصريح.

استخدم عنوان Tailscale HTTPS الفعلي الموضح أعلاه للوصول من الهاتف؛ لا تعرض المنفذ مباشرة للإنترنت ولا تستخدم عنوان الاستضافة المثال. عرض السوق المباشر على الهاتف لا يجعل الهاتف أو Telegram يشغّل البوت المستمر.

افحص حالة السوق الفعلية وجرّب Testnet وأوامر الحماية قبل المال الحقيقي. الحاسوب والحساب يجب أن يكونا في موقع تسمح Binance بالاستخدام منه. احتفظ بنسخة من `backend/data/bot.sqlite3` وملفات SQLite المصاحبة عند إيقاف الخدمة؛ حذف السجل مع مراكز مفتوحة يفقد سياق إدارتها. لم تُرسل رسائل Telegram أو أوامر تداول حقيقية أثناء اختبارات هذه الإضافة.
